# 专家子代理包（cuckoo-agents-pack）

为 [Cuckoo Code](https://github.com/wangyongpeng90/cuckoo-code) 增加 5 个专家子代理，用于委派复杂任务。

## 什么是子代理

子代理是**独立上下文的 AI 对话**。当你用 runAgent(name, task) 委派任务时，子代理在自己的上下文中完成工作，只把结果摘要返回主对话——**不污染当前上下文**。

适合委派的场景：大范围搜索、独立分析、代码审查、写测试等。

## 为什么需要这个插件

Cuckoo Code 内置了通用子代理能力，但缺少针对特定领域的专家。本插件提供 5 个经过打磨的专家子代理，每个都有明确的职责和方法论。

## 包含子代理

| 子代理 | 职责 | 适用场景 |
|---|---|---|
| code-reviewer | 系统性代码审查 | 改完代码、提交前 |
| test-engineer | 编写/补全单元测试 | 需要加测试时 |
| security-auditor | 安全审计 | 关注安全时 |
| debugger | 系统化排查 bug | 遇到报错、行为不符 |
| doc-writer | 生成文档 | 需要写文档时 |

## 子代理详解

### code-reviewer — 代码审查员

职责：独立、严格地审查指定代码，找出真实问题。

审查维度：正确性、错误处理、安全、并发、性能、可读性。

输出：每条问题标注位置、严重度、建议改法；最后给总评。

原则：只报真实问题，不凑数。

### test-engineer — 测试工程师

职责：为目标代码编写高质量单元测试。

原则：真实集成优先，只 mock 外部边界；覆盖失败路径和边界值；写完跑一遍确认通过。

输出：测试文件路径、覆盖行为、未能覆盖的行为及原因、测试运行结果。

### security-auditor — 安全审计员

职责：聚焦真正可被利用的安全问题。

检查项：注入、密钥泄露、路径穿越、鉴权、反序列化、XSS/CSRF。

规则：只报可利用的，不报"理论上可能"；区分高危和加固建议。

### debugger — 调试专家

职责：系统化定位问题根因，不靠猜。

步骤：读完整错误 → 复现 → 缩小范围 → 找根因 → 验证修复。

输出：现象、根因、修复、验证方法。不确定时明确说"这是猜测"。

### doc-writer — 文档工程师

职责：为目标代码/项目生成准确、实用的文档。

原则：先读代码再写；写"为什么"和"怎么用"；关键 API 给示例。

输出：文档内容、覆盖范围、待确认的点。

## 用法

### 在主对话中委派

直接说"用 code-reviewer 审查 src/app/entry.ts"，AI 会自动调用 runAgent('code-reviewer', '...')。

### 手动调用

    runAgent('code-reviewer', '审查 B:/project/src/app/entry.ts 的代码')

子代理完成后返回结果摘要。

## 安装

### 方式一：从插件市场安装（推荐）

1. 打开 Cuckoo Code
2. 进入「插件」页面
3. 搜索 cuckoo-plugin
4. 找到「专家子代理包」点击安装
5. 启用插件

### 方式二：手动克隆

    git clone https://github.com/jiangchengnay/cuckoo-agents-pack.git ~/.cuckoo/plugins/cuckoo-agents-pack

安装后在插件页启用即可。

## 特性

- **纯提示词，零执行** — 不含任何可执行代码，启用时不会弹出安全警告
- **独立上下文** — 子代理在独立对话中工作，不污染主对话
- **开箱即用** — 装完即生效，无需配置
- **标准插件格式** — 遵循 Cuckoo Code 插件规范

## 常见问题

**Q：子代理和技能有什么区别？**
A：技能是"操作指南"，在当前对话中生效；子代理是"独立助手"，在独立上下文中执行任务后返回摘要。

**Q：子代理会消耗更多资源吗？**
A：子代理会启动一个新的 AI 对话，会比直接在主对话中处理消耗更多——但它能避免主对话上下文被污染，长对话中反而更高效。

**Q：可以同时用多个子代理吗？**
A：可以。你可以依次调用不同的子代理，每个都在独立上下文中完成。
